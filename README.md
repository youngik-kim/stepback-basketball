## 🤝 짝꿍 승률 계산기 (조합 예측)

상단 요약 카드 아래 **`🤝 짝꿍 승률 계산하기 ›`** 버튼 → 바텀시트. 회원·게스트 1~7명(또는 게스트(첫출전))을 고르면 **같은 팀으로 함께 출전한 경기**만 모아 예상 승률을 바로 계산합니다.

- **계산식**: 주차별 로스터×팀 성적을 근거로, 조합 안의 모든 짝(pair)이 같은 팀이던 경기의 팀 성적을 합산 → `Σ짝 동반승 ÷ Σ짝 동반경기` = 짝 승률의 동반경기 가중 평균. 1명은 그 선수의 누적 승률입니다. **동반경기 = 승+무+패**, 승률 = 승 ÷ 동반경기(무승부는 분모에만) — 개인 승률과 같은 기준입니다.
- **팀 수 구분 없음**: 2파전·3파전을 나누지 않고 **모든 회차(45회차·기록지 46장)를 한 번에 합산**한 단일 계산입니다. 화면에도 `모든 회차 통합 기준` 한 줄만 표시합니다.
- **표본 표기**: 표본이 0인 짝은 분모에서 빼고 `짝 10쌍 중 9쌍 표본`처럼 표시, `표본 적음`(8경기 미만) 배지. 조합 전체 표본이 없으면 `표본 없음` + 개별 승률 단순평균을 `참고값(예측이 아닙니다)`으로 보여 줍니다.
- **포지션 구성 요약**: 결과 카드에 `PG · SG · SF · PF · C`별 인원과 복수 포지션 인원을 한 줄로 표시(계산식에는 포지션 미반영).
- **5인 자동 랭킹**: 정규 회원 15명 기준 **C(15,5)=3,003개 조합 전수** 탐색. 표본 필터 `조합 내 동반 경기 합 ≥ 6` + `짝 10쌍 중 8쌍 이상 표본`, 최고 5 / 최저 5 표시. **포지션 균형 조건**(가드 PG+SG 2~3명 · 포워드 SF+PF 2~3명, 복수 포지션은 유연 배정)이 기본 적용되고 `포지션 균형 맞춘 조합만` 토글로 해제할 수 있습니다(균형 후보 2,446개 / 전체 3,003개). 상단에 조건 문구(`5인 · 가드 2~3 · 포워드 2~3`)와 후보 수를, 각 행에 `포지션 구성`·`균형`·`표본 충분/적음` 배지를 표시합니다. 후보가 0개면 표본 필터 → 균형 조건 순으로 자동 완화하고 화면에 안내합니다.
- **포지션 미등록 시**: 로스터·이 기기 저장값에 포지션이 없는 선수가 있으면 **균형 조건을 자동 비활성화**하고 `포지션 정보 없음 — 균형 조건 미적용` + 미등록 선수 목록을 보여 줍니다(개인 카드에서 포지션을 입력하면 자동 적용). 이때도 랭킹·수동 계산은 정상 동작합니다.
- **게스트**: 기본 `게스트 포함`(ON). 게스트 칩에는 `게스트`·(8경기 미만)`적음` 배지가 붙고, 결과에는 `게스트 동반 표본 N경기 · 참고값` 안내가 나옵니다. 자동 랭킹은 **정규 회원만** 대상입니다.
- **게스트(첫출전)**: `+ 게스트(첫출전) 추가`로 이름(8자)·포지션(복수)·가정 승률(0~100%)·가정 표본(1~30경기)을 넣어 시뮬레이션합니다. 게스트(첫출전)와의 짝은 전부 가정값으로 계산하고 결과에 `시뮬레이션` 배지와 `실제 기록이 아닌 가정값` 안내를 답니다. 이 기기(`localStorage: stepback-fake-players-v1`)에만 저장되고 실제 기록·랭킹·승률표는 오염되지 않습니다.

- **결과 후**: 그 회차 카드 안에 프리뷰가 **접기/펼치기** 블록으로 남고, `예상 ↔ 실제 비교` 표에 팀별 **예상 승률 · 실제 전적·승률 · 예상 순위 → 실제 순위(✓/✗)** 가 함께 나옵니다. `주간 결과 전체` 아코디언에도 `프리뷰` 배지와 함께 같은 비교가 보존됩니다.
- 프리뷰가 없는 회차는 아무 것도 표시하지 않습니다.

## 매주 갱신 방법

```bash
# 1) 기록지 내용을 basketball/stepback-records.md · stepback-guests.md ·
#    개인 스탯표(basketball/2026-11-22-스텝백-개인스탯.md, basketball/2026-10-25~11-15-스텝백-개인스탯.md)에 반영
#    (경기 전 예상은 basketball/stepback-match-preview.md 에 같은 형식으로 추가)한 뒤
python3 src/build_data.py      # -> src/data.json (평문, 커밋 금지) + 기록지 표와 자동 대조 검증
python3 src/build_site.py      # -> index.html (ENC_DATA 암호화) + robots.txt
LD_LIBRARY_PATH="$(cat ../.libs/ldpath.txt)" python3 src/verify.py   # (선택) 390×844 / 1280×800 렌더링·기능 검증
```

- **짝꿍 승률 계산기·5인 랭킹은 별도 데이터가 없습니다** — `data.json` 의 주차별 로스터·팀 성적에서 브라우저가 직접 계산하므로, 위 두 명령만 다시 돌리면 조합 예상 승률도 자동으로 최신 기록 기준이 됩니다.
- 주간 경기 결과·승률을 갱신한 주에는 `src/template.html` 의 `CHANGELOG` 맨 위에 `{ date: 'YYYY-MM-DD', tag: '기록', items: ['N회차(M/D) 경기 결과·승률·개인 스탯 반영'] }` 를 추가하고 다시 빌드합니다.

- `build_data.py` 는 주차별 로스터×팀 성적에서 개인 승·무·패·출전·2파전/3파전을 **다시 계산해 기록지 표와 대조**합니다. 불일치가 있으면 목록을 출력하고 종료코드 1로 끝납니다.
- 입장 코드는 `site/.entry-code` 파일(또는 `--code`, `STEPBACK_ENTRY_CODE`)로 넣습니다.

## 보안

- `index.html` 에는 `<meta name="robots" content="noindex, nofollow">`, `robots.txt` 는 `User-agent: * / Disallow: /`.
- 데이터는 **PBKDF2-SHA256 20만 회 → AES-256-GCM** 으로 암호화해 `const ENC = {…}` 로만 내장됩니다. HTML 소스에 선수 이름·전적·입장 코드가 평문으로 남지 않습니다(빌드 시 자동 검사).
- 입장한 기기는 `localStorage` 에 **복호화 키만** 저장해 재입장을 생략합니다(푸터 잠금 버튼 없음 — 브라우저 저장 데이터를 지우면 다시 잠깁니다).
- 입장 코드를 **2회 이상 틀리면** `제한된 공간입니다. 관리자에게 입장코드를 문의해 주세요.` 안내로 바뀝니다.
- **절대 저장소에 올리면 안 되는 파일**: `src/data.json`(평문 명단), `.entry-code`. `.gitignore` 에 포함되어 있습니다.
- 배포물은 `index.html` · `robots.txt` · `.nojekyll` 뿐입니다.
